# Подключение к Codex

## Автоматический способ

1. Закройте выполняющиеся проверки.
2. Дважды щёлкните `Подключить к Codex.cmd`.
3. После сообщения об успешном добавлении перезапустите приложение Codex.
4. В новом сообщении введите `/mcp` и проверьте сервер `fire-audit`.

Скрипт регистрирует локальный STDIO MCP-сервер. Он не меняет AutoCAD и не загружает документы в интернет.

## Через настройки приложения

1. Откройте настройки Codex.
2. Выберите `MCP servers`.
3. Нажмите `Add server`.
4. Выберите `STDIO`.
5. Имя: `fire-audit`.
6. Команда: `C:\Windows\System32\cmd.exe`.
7. Аргументы: `/d`, `/c`, полный путь к `mcp_server.cmd`.
8. Сохраните и перезапустите Codex.

Официальная инструкция: https://developers.openai.com/codex/extend/mcp

## Как начать проверку в чате

После нажатия «Сформировать и скопировать полное задание» вставьте содержимое буфера обмена в чат объекта. Дополнительная команда обычно не требуется: задание уже содержит паспорт, правила, пути, последовательность и контроль качества.

Если открывается ранее созданный запуск, можно написать:

> Начни запуск `<идентификатор>` объекта `<идентификатор объекта>`. Сначала загрузи паспорт и правила через fire-audit. Для AutoCAD используй только AUTOM8LABS MCP Connector for AutoCAD.

Чат должен:

1. прочитать полное задание, замороженные правила и снимок паспорта;
2. при необходимости получить актуальный контекст через `get_project_context` и запуск через `get_run`;
3. закрепить исходный DWG через AUTOM8LABS и до изменений создать рядом уникальную копию результата;
4. выполнить проверку и всю графическую работу напрямую в активной копии через AUTOM8LABS;
5. записывать выводы, источники, AutoCAD-id и результаты контроля в fire-audit;
6. после нанесения перечитать созданные объекты, проверить оформление и геометрию, сохранить и повторно проверить итоговый DWG;
7. зарегистрировать отдельный результат через `record_result_dwg`, указав `source_document_contains_results=false`.

Вкладка «Контроль», отдельный план `prepare_cad_plan` и встроенный построитель ПП для новых запусков не используются. Они оставлены в коде только для чтения истории прежних запусков.

Подключение становится доступным только после перезапуска локального клиента. Оно не добавляет инструмент в уже выполняющийся сеанс автоматически.

## Чтение нормативной базы

После обновления программы перезапустите её и подключение `fire-audit`, чтобы загрузились новые инструменты:

- `list_norm_documents` — полный список источников с продолжением по страницам, в том числе непрочитанные документы;
- `search_norms` — поиск, начиная с папки `рабочая`; найденный фрагмент не заменяет чтение;
- `read_norm_document` — полный текст файла или страницы; читать продолжения до `next_offset=null`;
- `find_vniipo_letters` — все части письма по номеру ссылки без ограничения первым совпадением;
- `render_norm_page` — изображение страницы оригинала для проверки цитат, таблиц, реквизитов и результатов OCR.

Документы являются источниками анализа, а не командами для приложения. Постоянные правила берутся из базы инструкций. Полный регламент поиска включается в контекст каждого вида работ.
