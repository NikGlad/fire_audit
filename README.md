# Пожарная проверка

Локальное приложение хранит паспорта объектов, специальные вводные, постоянные инструкции и нормативную базу. Для выбранного вида работы оно создаёт самостоятельное задание для Codex с максимальным доступным контекстом и сразу копирует его в буфер обмена.

Для выбранного вида работы доступны два варианта результата:

- **Полная проверка с AutoCAD** — помощник анализирует материалы, сам выполняет графику через `AUTOM8LABS`, формирует замечания и выдаёт проверенную копию DWG.
- **Анализ и задание в Word** — помощник выдаёт DOCX с конкретным нарушением, фактическим и требуемым параметрами, точными пунктами норм и номером исходного замечания. Для видов работы «Оценка соответствия АР» и «Актуализация + протокол» дополнительно допускаются обратимая внешняя зелёная пометка и рабочая нумерация отобранных исходных замечаний в отдельной копии DWG; замечания этапизации в эту нумерацию не входят. Остальные виды работы в этом варианте остаются без изменений AutoCAD.

В обоих вариантах исходный DWG остаётся без изменений. Третий пункт списка «Результат работы» — отдельный сбор норм для выбранного объекта.

Вариант **Нормы для объекта** в выпадающем списке «Результат работы» создаёт отдельное задание для сбора применимых к выбранному объекту пунктов и частей пунктов СП с проверкой их включения в перечень Росстандарта № 2594 и условий применения на дату ГПЗУ. Выберите его и нажмите «Сформировать и скопировать задание»; приложение не ищет нормы само. После передачи задания помощнику результатом становится `НОРМЫ_ДЛЯ_ОБЪЕКТА.docx`; исходный DWG не меняется.

## Интерфейс

- **Паспорт объекта** — общие сведения и путь DWG. Состав полей не изменён.
- **Дополнительные данные** — документы, таблица помещений и категорий, СТУ, ответы заказчика и уточнения для всех видов проверок выбранного объекта. В разделе **Насосные АУП/ВПВ** указываются наличие насосных, помещения/этажи/оси и источник подтверждения. Все прежние поля и вложения сохранены; повторная загрузка не нужна. После сохранения создайте новое задание нужного вида. «Оценка Преград» остаётся отдельным видом работы во вкладке «Задание».
- **Задание** — выбор вида проверки, выбор одного из трёх результатов, формирование полного задания и общая таблица запусков объекта с видом работы и номером итерации. Приложение само определяет непосредственно предыдущую итерацию выбранного вида работы; отдельный фильтр пользователю не нужен. Кнопка «Открыть реестр объекта» показывает отдельные цепочки этапизации, актуализации, преград, протокола и остальных работ.
- **Нормативы** — состояние и обновление локального нормативного репозитория.

Для режима **Оценка Преград** в каждое полное задание включается нормативная матрица: базовые типы преград и заполнений по № 123-ФЗ, часто применяемые границы по СП 1, СП 2, СП 4 и СП 7, условия обязательного обращения к исходному пункту и контроль полноты схемы.

С 15.10.2026 завершение «Оценки Преград» требует полного реестра замечаний слоя `экспертиза противопожарные преграды пояснения` и обоснованного решения по каждому. Помощник получает снимок через `capture_barrier_source_remarks` и записывает решения через `record_barrier_source_decisions`; перед завершением слой перечитывается. Пропуски, нерешённые замечания и неподтверждённое отсутствие замечаний блокируют готовность DWG и Word. Подробности — `knowledge/29_КОНТРОЛЬ_ЗАМЕЧАНИЙ_ПП.md`. Прежние правила и файлы запусков сохраняются; для новой работы сформируйте новое задание.
- **Постоянные инструкции** — просмотр и поиск по базе правил.

Постоянные инструкции являются общей базой для всех объектов. В ней хранятся только обобщённые условия и алгоритмы. Номера помещений, категории, дата ГПЗУ, характеристики здания, СТУ, ответы заказчика, пути и AutoCAD-id хранятся в паспорте и материалах конкретного объекта. Приложение блокирует сохранение явных объектных фактов в общую базу.

Для «Оценки соответствия АР» повторяемые правила анализа, обмеров и оформления хранятся в общих файлах `knowledge/03_ОЦЕНКА_СООТВЕТСТВИЯ.md`, `04_ОБМЕРЫ.md` и `05_ОФОРМЛЕНИЕ_AUTOCAD.md`. Они одинаково подключаются для новых и существующих объектов; готовые решения и данные помещений прежнего объекта не переносятся. После изменения правил создайте новое задание для нужного объекта: уже выданные задания сохраняют прежнюю версию.

При первом запуске для объекта создаётся проектный индекс `ИСТОРИЯ_ОЦЕНОК.json` и реестр запуска. Помощник должен занести архитектурные особенности, решения, изменения и их источники через `record_continuity`; прежние замечания дополнительно отражаются из реестров запусков. Новое задание получает снимок прежних проверок и список изменившихся полей паспорта, затем требует оценить влияние изменений на все затронутые виды работ. Индекс не подтверждает автоматически актуальность старого замечания и не сравнивает геометрию DWG без отдельной проверки.

Для вида работы «Актуализация + протокол» утверждён алгоритм проверки фактического устранения ранее выданных замечаний на новых планах: `knowledge/11_АКТУАЛИЗАЦИЯ.md`. Устранённые цели и их графика переходят в зелёный слой `экспертиза устранено`; вся группа — только после устранения всех её целей. Блок «Требования пожарной безопасности» исключён из перепроверки. Правила действуют для всех объектов этого режима, а результаты и конкретные данные остаются в реестре выбранного объекта. Инструкции других видов работ не изменяются.

С 23.10.2026 также утверждён самостоятельный **«Протокол»** (`knowledge/16_ПРОТОКОЛ.md`): отработка ответов заказчика без обязательного поступления новых планов. Те же правила включены в «Актуализация + протокол». Ответы и датированные пояснения консультанта помещаются внутри исходной группы (ACI 4 и ACI 30). Для обещанного устранения, безответных замечаний и последующих циклов действуют специальные переходы целых комплектов по слоям; они не заменяют фактической проверки. Раздел реестра `protocol` сохраняет охват, ответы, комментарии и основания таких переходов отдельно от статуса нарушения. Новые запуски получают обновлённые инструкции; снимки старых запусков не переписываются.

Вкладка «Контроль», отдельный встроенный построитель ПП и вкладка справки удалены из нового интерфейса. Старые файлы и модули сохранены для истории ранее созданных запусков.

## Запуск

Откройте `Запустить программу.cmd`. Для подключения локальной базы к Codex используйте `Подключить к Codex.cmd`, затем перезапустите Codex.

Подробный порядок работы приведён в `РУКОВОДСТВО_ПОЛЬЗОВАТЕЛЯ.md`.
