# Структура папок

```text
Пожарная_проверка/
├── app.py                         пользовательское окно
├── cli.py                         команды для диагностики
├── mcp_server.py                  подключение к чату Codex
├── Запустить программу.cmd        запуск окна двойным щелчком
├── Подключить к Codex.cmd         регистрация MCP-сервера
├── config/
│   └── app.json                   адрес GitHub и общие настройки
├── knowledge/                     постоянные утверждённые правила
├── templates/                     пустые формы объекта и результата
├── projects/                      отдельные папки объектов
│   └── ГГГГ-Краткое_название/
│       ├── project.json           вводные только этого объекта
│       ├── sources/               материалы объекта
│       └── runs/                  отдельные проверки
├── inbox/
│   └── НОВЫЕ_ИНСТРУКЦИИ.md        новые правила до утверждения
├── data/
│   ├── normative_cache/           локальное зеркало GitHub
│   └── index/norms.sqlite3        служебный поисковый индекс
└── logs/                          резервные копии изменений правил
```

## Имена папок объектов

Рекомендуемый формат:

`ГГГГ-ММ-ДД_Краткое_название`

Примеры:

- `2026-09-02_Храброво_АБК`
- `2026-09-02_Склад_с_АБК`

В одной папке должен находиться только один проверяемый объект. Нельзя заменять `project.json` паспортом другого здания.

## Материалы объекта

В `sources` рекомендуется хранить:

- исходный DWG или ярлык/текстовый файл с путём к нему;
- экспликацию;
- фасады и разрезы;
- исходные данные заказчика;
- ответы на запросы;
- СТУ и расчёты;
- дополнительные инструкции только для этого объекта.

Проектный DWG программа не копирует и не изменяет самостоятельно.
