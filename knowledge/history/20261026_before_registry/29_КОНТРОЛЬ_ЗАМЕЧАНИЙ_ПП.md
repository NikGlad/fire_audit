# Обязательный контроль всех исходных замечаний при оценке преград

Дополнение пользователя от 15.10.2026 для режима «Оценка Преград». Действует для полной работы с DWG и для анализа с результатом в Word. Сохраняет все прежние требования документов 18, 21, 23, 26 и остальных подключённых правил. Сбор норм для объекта остаётся отдельным видом работы.

## Что обязательно проверить

Полностью прочитать слой `экспертиза противопожарные преграды пояснения` во всех пространствах модели и листов, независимо от видимости слоя. Рассмотреть каждое замечание, ответы заказчика, даты и последовательность редакций, выбранные варианты, все требования внутри одного текста, каждый луч и его фактическую цель. Учитывать замечание — значит принять и обосновать решение; это не означает автоматически переносить любую исходную формулировку в итоговую схему. Применимость норм, СТУ и действующие исключения графики сохраняются.

## Закрепление источника

1. Помощник вызывает `capture_barrier_source_remarks(slug, run_id)` через приложение. Процедура сама читает слой официальным коннектором AUTOM8LABS, проверяет все страницы выгрузки, выполняет два полных чтения и сверяет состояние DWG. Она не открывает, не переключает, не изменяет и не сохраняет чертёж.
2. Первичный снимок обязательно получить именно из исходного DWG. Он отдельно сохраняется в `ОРИГИНАЛ_ЗАМЕЧАНИЙ_ПП.json`. После этого допускается чтение отдельной копии результата данного запуска; копия не может подменить исходный перечень: все исходные объекты должны сохраниться без изменений. Добавленные в копии объекты также учитывать. Для анализа в Word используется исходник. Чужой документ не принимается. Снимок связан с исходным путём и конкретным запуском, хранит тексты, свойства, AutoCAD-id и контрольную сумму. Не подменять снимок вручную подготовленным списком.
3. Ошибки чтения, обрезанная выгрузка, повторные страницы, неподдержанные вложенные блоки/XREF/proxy и отсутствие доступа не означают отсутствие замечаний. Пока полнота чтения не установлена, завершение запрещено. Вложенные источники требуют отдельного решения способа их полного чтения; запрет автоматически не разрешает расчленять блоки или менять исходный DWG.
4. Пустой или отсутствующий слой допустим только после успешной полной инвентаризации и отдельного обоснования `none_found_reason`. Если объекты есть, но замечаний нет, каждый объект должен иметь собственное обоснованное исключение.

## Решение по каждому замечанию

Помощник ведёт `barrier_assessment.source_remarks` в реестре запуска через `record_barrier_source_decisions`. Можно сохранять работу частями. Для исправления ошибочной группировки используется `delete_decision_ids`: прежние записи остаются в истории, исходные объекты DWG не удаляются, завершённость сбрасывается. Каждое решение связано с `inventory_digest` текущего снимка и содержит:

- уникальный `id` и `source_entity_ids` исходного текста, относящихся ответов, лучей и иной графики;
- `kind=remark`, содержание и итог в `summary`, обоснование `basis`;
- `context_review`: рассмотренные ответы, даты, варианты, требования и цели; отсутствие соответствующих данных указать явно;
- `all_requirements_reviewed=true` только после разбора всех требований и целей данного замечания;
- конечное решение `applied` (учтено), `already_satisfied` (выполнено в проекте), `not_applicable` (обоснованно неприменимо) либо `superseded` (заменено актуальной редакцией);
- `result_refs`: AutoCAD-id результата, ссылка на запись реестра либо конкретный раздел Word. Для учтённого/выполненного требования и замены ссылка обязательна; для неприменимости обязательны контекст и обоснование;
- `status=resolved` только после завершения решения. `pending`, `needs_clarification`, неизвестный статус, отсутствующее решение и неподтверждённое допущение блокируют завершение.

Каждый исходный AutoCAD-id должен быть учтён ровно один раз. Объединять текст с его ответами и графикой в одну запись разрешено; объединять независимые замечания для сокрытия нерешённых вопросов запрещено. Один текст с несколькими требованиями требует явного рассмотрения каждого из них в решении.

Служебный объект допускается исключить только отдельной записью `kind=non_remark`, `decision=non_remark`, с одним AutoCAD-id, содержанием и конкретным обоснованием. Для текста дополнительно обязательны контекст и `non_remark_kind`: `legend`, `heading`, `measurement` или `reference_note`. Эти категории не разрешают объявлять замечания служебными. Размеры простенков, которые прежнее правило требует сохранять в этом слое, остаются в DWG и отдельно учитываются как обмеры.

## Запрет преждевременного завершения

Приложение не принимает завершённый контроль качества, регистрацию готового DWG или готового Word и итоговую проверку `validate_run(for_application=true)`, пока реестр не охватывает весь снимок и не содержит конечного решения по каждому замечанию. Один флаг «пояснения прочитаны» и общие отметки качества этот контроль не заменяют. Незавершённые материалы разрешено сохранять как рабочие.

Перед каждой операцией завершения приложение заново читает слой активного разрешённого DWG. При изменении исходных объектов, текста или свойств прежние решения и отметки завершения переходят в историю, а контроль требуется выполнить заново по новому снимку. Нерешённый вопрос сохраняется в реестре; он не становится закрытым из-за создания отчёта или сохранения чертежа.

После регистрации копии результата итоговое чтение выполняется именно из закреплённой копии. Переключение на исходник не заменяет проверку результата. Фактический документ закрепляется на всё время чтения; смена активного DWG прерывает контроль. Для исходного файла сохраняются SHA-256, размер и время изменения: изменение исходника после снимка блокирует завершение до повторного чтения исходника и проверки решений. Недоступный исходный файл также блокирует завершение. Выгруженная или не подтверждённая как полностью прочитанная внешняя ссылка не принимается за пустой источник.

История объекта также проверяет этот реестр: наличие файла результата или флага `work_completed` без закрытого контроля не делает оценку завершённой. Старые файлы и правила запусков не перезаписываются; для новой работы создать новое задание с актуальной инструкцией. При продолжении старого запуска новый контроль также обязателен перед его завершением.

После закрытия этого реестра выполнить все прежние тематические проверки преград, помещений, перекрытий, проёмов, легенды, графики и нормативного анализа. Новый контроль дополняет их и не отменяет.
