# История объекта и контроль пропусков

Механизм действует для всех объектов и видов работ. Дополнительные команды от заказчика не нужны: обязанности помощника включены в общие правила, задания и инструкции MCP-сервера.

## Что сохраняется автоматически

При сохранении паспорта, запуска или реестра через приложение в локальный `ЖУРНАЛ_СОБЫТИЙ.sqlite3` добавляется версия изменённых данных. Для замечания сохраняются прежнее и новое содержимое, включая основание решения. Записи журнала не заменяются; API не предоставляет удаления. Для больших реестров сохраняются изменения отдельных позиций. Повторная запись тех же данных не создаёт новую версию.

Журнал принадлежит одному объекту и связан с общей историей и сводом преемственности. Другие виды проверок могут читать прежние события по идентификаторам запусков. Журнал и сведения заказчика не публикуются в Git.

Прямые изменения JSON вне API выявляются при очередном чтении журнала или итоговой проверке. Если между такими обращениями файл несколько раз переписали вручную, невидимые промежуточные версии восстановить нельзя. Поэтому штатные изменения нужно выполнять через API приложения.

## Что обязан записывать помощник

Сразу после получения ответа, документа, нового плана, изменения задания, возникновения вопроса или принятия решения — `record_history_event`. Запись содержит дату события, точный источник, исходный текст отдельно от интерпретации, связи с замечаниями, нормами и планами. Для локального источника передаётся `source_path`: приложение сохраняет SHA-256 версии. Для корректировки используется новый id и `supersedes`; исходное событие остаётся.

После записи нужно обновить относящиеся факты и решения текущего реестра, а также `record_continuity`. Журнал не заменяет проверку, паспорт или рабочий реестр. При изменении плана фиксируются старый и новый лист, места изменений и влияние на прежние замечания и другие виды работ. Исходные версии файлов сохраняются по правилам выбранного режима.

## Сверка перед завершением

1. После регистрации результата и контроля качества выполнить `validate_run`.
2. Прочитать `get_run_history` до `has_more=false`, используя `next_after_seq`. Сопоставить события со всем доступным диалогом, файлами, планами и предыдущими проверками. Пропущенные события сначала добавить.
3. Выполнить `reconcile_run_history`: указать последнее сверенное сообщение, перечень источников всех четырёх видов, все `review_event_ids`, а для каждого ручного события — решение, причину и доказательство. Локальные файлы перечислить по одному с `path`; приложение проверяет их SHA-256. Если источников определённого вида нет, это явно поясняется в `reference`.
4. Выполнить итоговый `validate_run(for_application=true)`. Новые события, изменения паспорта/реестра или файлов после сверки требуют повторной сверки.

`unresolved` означает сохранённый открытый вопрос. Он не подтверждает соответствие и не отменяет остальные ограничения завершения проверки. Автоматические снимки также должны быть рассмотрены, но не требуют искусственного создания отдельного ручного события для каждого служебного поля.

Новые запуски требуют сверки истории при итоговой проверке. Старые архивные запуски не переписываются и не объявляются задним числом полными. При продолжении старого запуска запись ручного события или сверки включает такой же контроль; до этого выдаётся предупреждение о непроверенной полноте истории. В передаваемое задание добавляется актуальное указание по журналированию без замены сохранённого снимка прежних правил.

## Граница контроля

Приложение не получает весь чат автоматически. Оно обнаруживает отсутствие итоговой сверки, неучтённые зарегистрированные события и изменения после сверки. Честность перечня доступных сообщений и правильность анализа проверяет помощник. Недоступная переписка и неизвестные прежние версии должны быть обозначены как ограничения, а не выданы за восстановленную историю без пропусков.

После обновления уже запущенное приложение и MCP-сервер нужно перезапустить для загрузки нового кода. Объектные данные при обновлении не переносятся в репозиторий и не удаляются.
